# Effective context

Class: **learn.** Accepted 2026-10-01. The delta is on the live retrieve, check_sync, and run specs. This folder is archived.

Live text and the open change stay labeled. The implementation context is the change. Canonical synchronization is pending until accept. The open change is not merged into the live slice.

A readiness warning fires when an open change names a Phase 1 id. Phase 1 stays valid. The warning is not a validate failure. Nothing writes `realized_by`.

An English `must:` with no `run.unittest`, `run.argv`, or `test:` is evidence `none` and status `UNVERIFIED`. A bound command that passes is `VERIFIED`. That means the command exited 0. `run` still exits 0 when every sensor is `UNVERIFIED`.

`context <target>` is the task slice. A path with no `realization.paths` match stays unmapped. The command does not read the file and does not invent a component.

`specplane-explain` answers from those four sources and keeps them apart. It is a skill, not a fifth MCP tool, and it does not take `--by` flags or assign owners.
